# VoteRisk code review — 2026-09-10

This review compares the repository against the intended EDAS-vs-VoteRisk experiment.  The reviewed code is on branch `review-fixes-20260910`.

## Critical findings fixed

1. **VoteRisk penalty direction was reversed.**  The old code used a positive delta for above-average risk, which made a negative wrong advantage *less* negative.  The reviewed implementation uses `Delta = -lambda * base * (R_i - R_bar)` so genuinely dangerous wrong modes receive stronger negative updates.

2. **Max-normalising risk deviations removed the key finite-budget signal.**  The old `T=(R-R_bar)/max|R-R_bar|` made a harmless dominant wrong mode receive almost the same shaping magnitude as a genuinely competitive mode.  The reviewed implementation preserves the absolute vote-risk difference and does not max-normalise it.

3. **Risk centring was mode-unweighted, not sample-weighted.**  This violated the intended zero-sum redistribution across wrong trajectories whenever wrong-mode sizes differed.  The reviewed implementation uses `R_bar = sum_j n_j R_j / N_w`, so desired deltas sum to zero across wrong samples before clipping.

4. **Configured G could differ from the actual prompt group size.**  The reviewed implementation uses `len(indices)` for the probability model and logs any mismatch with configured rollout `G`.

5. **EDAS baseline hyperparameters were not the official DAPO recipe values.**  `run_train.sh` used alpha/beta `0.2/0.2`.  The EDAS DAPO launcher uses `0.4/0.3` with kappa `2.0`.  The reviewed training script now uses `0.4/0.3/2.0` for EDAS.

6. **`--smoke` did not actually make training short.**  It still kept two full epochs.  The reviewed script sets `trainer.total_training_steps=2` by default for smoke tests.

7. **Pass@k evaluation was not standard Pass@k.**  The old evaluator only checked whether the first k generated samples contained a correct response.  The reviewed evaluator uses the standard estimator `1 - C(N-c,k)/C(N,k)` from the full N-sample pool.

8. **Maj@k was order-dependent.**  The old evaluator voted once on the first k samples.  The reviewed evaluator repeatedly subsamples k responses from the same fixed N=64 pool (default 2000 resamples/problem), uses conservative tie-as-failure, and reports tie rates.

9. **Evaluation answer modes were string-normalised rather than math-equivalence clustered.**  The reviewed evaluator uses `mathruler.grade_answer`, matching the training-side EDAS/VoteRisk equivalence logic.

10. **No-answer and truncation were conflated with real wrong modes.**  The reviewed evaluator treats unparseable answers as abstentions in Maj@k, reports `no_answer_rate` and `truncation_rate`, and excludes empty strings from wrong-mode concentration metrics.

11. **Evaluation reruns appended duplicate records.**  The reviewed evaluator overwrites each method's per-dataset/per-problem result files on a new evaluation run.

12. **Sequential evaluation selected the oldest checkpoint.**  The old script used `ls -td ... | tail -1`.  The reviewed script selects the numerically largest `global_step_*` and merges FSDP actor shards to a HuggingFace checkpoint before vLLM evaluation when needed.

## Fairness invariant

The two full runs must share model, data, DAPO objective, optimizer, learning rate, rollout G, decoding distribution, lengths, effective training budget, reward/verifier, and evaluation settings.  The intended algorithmic difference is only the post-GRPO/DAPO wrong-trajectory advantage shaping signal: EDAS error-diversity versus VoteRisk finite-budget correct-vs-wrong vote threat.
